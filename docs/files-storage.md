# Files 私有持久存储

Files 默认关闭。启用前必须为所有主仓实例挂载同一份私有持久卷，并指定绝对路径；容器可写层、自动生成的临时目录和公开图片目录不能用作该存储。数据库记录与原始文件必须一起备份、一起恢复。配置校验能检查路径格式和有限配额，无法证明部署卷在容器重建后仍然存在，部署验收必须实际重建实例并核对原文件哈希。

推荐起始配置：

```yaml
gateway:
  files:
    enabled: false
    root: /var/lib/sub2api/files
    max_file_bytes: 209715200
    user_quota_bytes: 2147483648
    global_quota_bytes: 21474836480
    free_space_reserve_bytes: 1073741824
    lease_seconds: 300
```

确认私有卷挂载、可用空间、权限和备份后再将 `enabled` 改为 `true`。单文件最多 200 MiB；用户硬配额必须至少容纳一个最大文件，全局硬配额必须不小于用户硬配额。用户与全局配额必须为正数，不支持无限配额；可用空间保留量必须为正数，租约至少 60 秒。流式上传有独立的文件大小边界，不需要提高全局 JSON 请求体上限。

`root` 不提供默认值。其他默认值与上面的推荐值一致；关闭功能时允许不配置存储。启用后，不合法的配置会使启动校验失败，不会自动改成其他值。环境变量名称按现有配置规则映射，例如 `GATEWAY_FILES_ENABLED` 和 `GATEWAY_FILES_ROOT`。

## 身份与文件状态

通过主仓 `base_url` 访问 `POST /v1/files`、`GET /v1/files/{id}` 和 `GET /v1/files/{id}/content`。文件所有者是用户 `UserID`，上传时的 `APIKeyID` 仅作为来源和审计记录。同一用户换用当前仍获授权、绑定同一组的有效 key 后可以读取；同组其他用户看不到该文件。组权限以请求时的权限为准。

Files 使用独立认证路由，不运行模型选择或合成路由。文件管理不产生推理计费，余额或推理配额耗尽不阻止合法所有者读取已有文件；停用用户、停用 key、真实到期时间、IP 限制和当前组权限仍必须通过校验。订阅分组要求当前订阅授权仍有效，SimpleMode 也执行此检查；额度耗尽允许读取和上传，订阅撤销或到期则失去该组访问权。

本地文件上传完成只表示主仓已经持久保存原文件。返回的文件状态不得表示 BPS 已上传、已处理或可用于某个模型。向 BPS 的首次引用绑定和上游副本管理由后续阶段接入。

## 发布与回滚

先应用新增的 PostgreSQL 迁移，再在所有实例挂载私有卷并配置有限配额，最后启用 Files。迁移只新增 Files 专用持久化结构，不修改现有出站身份。原文件使用私有目录和私有文件权限，不能通过静态资源服务器公开。

回滚时先关闭 `gateway.files.enabled`，再回滚应用版本；保留新增表和持久卷，使新版本能够恢复原有 public ID 与原始字节。不要在常规应用回滚中删除表、清空存储目录或单独恢复其中一方。需要彻底删除时，应先停用所有 Files 写入实例，并另行安排数据清理和备份保留。

上传、读租约、暂存提交和 tombstone 通过 PostgreSQL 协调，不依赖单进程锁。上传取消、磁盘满或数据库失败时，不应留下可读取的半成品；崩溃遗留的暂存文件仅能在对应租约已失效且取得协调权后回收，不能按文件时间直接删除仍在上传的文件。

暂存恢复在启用功能的主仓启动时以及每次新上传前执行。启动时仍有效的旧租约会保留，过期后由下次启动或上传触发回收；当前阶段没有空闲时定时清理已完成文件的 worker。预留配额在清理确认前保留，数据库提交结果不确定时也采用相同的保守规则。

上传采用 multipart 流式读取，`purpose` 可位于文件之前或之后；只接受一个非空文件。文件名限 255 字节，拒绝路径分隔符、控制字符及无效 UTF-8。MIME 必须为允许的文档、文本、图片或 `application/octet-stream` 类型；原始内容不执行，也不通过响应中的 MIME 启动内联渲染。下载固定为 attachment、octet-stream，并带 `nosniff`、私有禁缓存和原文件 SHA256。

主服务器外层只对启用后的 `POST /v1/files` 使用独立的文件上限加 64 KiB multipart 预算；现有全局 JSON 请求体限制保持原值。文件流仍按配置的单文件字节数再次计数，因此 multipart 预算不会增加文件内容上限。
